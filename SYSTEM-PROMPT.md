### При проблемах с подключением к METAMCP (соединение есть, но отдаёт 0 инструментов)

```
Причина была не в регистрации и не в шлюзе Windows: в `global-localhost` был переполнен пул соединений MetaMCP (`190/100`), а сессии не истекали никогда (`SESSION_LIFETIME` не задан). Новая клиентская сессия не получала соединение с сервером `machine-host-windows`, сервер исключался из ответа, и endpoint отдавал `tools: []` с HTTP 200 — без ошибки. Инспектор видел инструменты потому, что подключается к серверу напрямую (`/mcp-proxy/server`), минуя пул.
```

Агентам нужно переподключить MCP-сессию: те, кто уже получил пустой список, держат его в кэше.
