# Конфигурация

## `.env`

В проекте нет одного общего конфигурационного файла: Linux-стек использует `.env`, а текущий Windows LOCAL — JSON-настройки и отдельный приватный файл секретов. Они не взаимозаменяемы. Ни один из файлов с секретами не следует добавлять в Git или отправлять в логи. Схема внутренней сети Hyper-V, WSL 2 и Windows-ВМ, её ограничения и откат описаны в [сетевом руководстве](wsl-hyperv-network.md).

### Linux: `~/mcp-global/config/.env`

Это главный пользовательский файл конфигурации глобального набора. Его создаёт `linux/install-global.sh`, если файла ещё нет. Если файл уже существует, установщик его не перезаписывает. Файл читается установщиком и `linux/run-global.sh` при запуске вспомогательных сервисов, синхронизации URL и регистрации MCP в MetaMCP. Ожидаемый формат — присваивания оболочки: `NAME=value`; комментарии начинаются с `#`. Файл выполняется через `source` в Bash, поэтому используйте только доверенное содержимое. Для значений со специальными символами используйте одинарные кавычки, если секрет не содержит одинарную кавычку; не оставляйте вокруг значения буквальные пробелы.

Начальный файл, создаваемый текущим установщиком (только если его ещё нет). Значения и закомментированность переменных совпадают с шаблоном; поясняющие комментарии здесь переведены и уточнены:

```dotenv
# Общие настройки LLM API по умолчанию; значения отдельных сервисов имеют приоритет.
LLM_API_ENDPOINT=https://api.openai.com/v1
LLM_API_KEY=
LLM_API_MODEL=gpt-4o-mini
LLM_API_PROVIDER=openai

# Graphiti: LLM и эмбеддинги используют общий адрес API и ключ; модели задаются отдельно.
# GRAPHITI_API_ENDPOINT=
# GRAPHITI_API_KEY=
# GRAPHITI_API_MODEL=gpt-4o-mini
# GRAPHITI_EMBEDDER_MODEL=text-embedding-3-small
# GRAPHITI_GROUP_ID=multfinite-mcp-kit-global

# Для LLM Cognee каждую общую настройку API можно переопределить отдельно.
# COGNEE_LLM_API_ENDPOINT=
# COGNEE_LLM_API_KEY=
# COGNEE_LLM_API_MODEL=gpt-4o-mini
# COGNEE_LLM_API_PROVIDER=openai

# Эмбеддинги Cognee настраиваются отдельно; пустые адрес, ключ и провайдер API
# наследуют общие значения, а модель эмбеддингов задаётся отдельно.
COGNEE_EMBEDDING_API_ENDPOINT=
COGNEE_EMBEDDING_API_KEY=
COGNEE_EMBEDDING_API_MODEL=text-embedding-3-small
COGNEE_EMBEDDING_API_PROVIDER=openai
COGNEE_EMBEDDING_DIMENSIONS=1536

# ── Neo4j & Qdrant ──────────────────────────────────────
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=mcp-neo4j-pass
# NEO4J_DATABASE=neo4j  # База Graphiti должна существовать заранее.
QDRANT_URL=http://localhost:6333

# ── Публичный адрес MetaMCP ──────────────────────────────
# Задайте публичный адрес (обычно HTTPS) и примените его к MetaMCP командой
# `bash linux/run-global.sh apply-metamcp-config`.
APP_URL=
# Если NEXT_PUBLIC_APP_URL не задан, используется APP_URL.
NEXT_PUBLIC_APP_URL=

# ── Интеграции ──────────────────────────────────────────
GITHUB_PERSONAL_ACCESS_TOKEN=
CONTEXT7_API_KEY=
# Для Google Drive нужна отдельная авторизация OAuth; см. README.
```

Пустые и закомментированные строки не задают ключ. Чтобы включить переменную, уберите `#` и укажите значение; например, необязательные `QDRANT_API_KEY` и `NEO4J_USERNAME` можно добавить вручную. Если в старом `~/mcp-global/config/.env` остался `OPENAI_API_KEY`, комплект его игнорирует: это имя не является параметром конфигурации. Для общего ключа используйте `LLM_API_KEY`. Внутри Graphiti `OPENAI_API_KEY` получает эффективный ключ из `GRAPHITI_API_KEY`, а если он пуст — из `LLM_API_KEY`; модель эмбеддингов задаётся отдельно через `GRAPHITI_EMBEDDER_MODEL`.

Пустые сервисные значения наследуются от соответствующих глобальных значений. Но созданный файл **явно задаёт** `COGNEE_EMBEDDING_API_PROVIDER=openai` и `COGNEE_EMBEDDING_API_MODEL=text-embedding-3-small`: они не изменятся при смене `LLM_API_PROVIDER` или старых алиасов, пока соответствующее новое значение не будет очищено или изменено. Для адреса API, модели и провайдера приоритет — новое сервисное имя, старый сервисный алиас, глобальное значение (где оно предусмотрено), встроенное значение по умолчанию. Старые демонстрационные значения `sk-your-openai-key-here`, `sk-or-v1-your-key-here` и `ghp_your_token_here` считаются пустыми для обрабатываемых скриптом ключей Graphiti/Cognee, GitHub и Context7.

Полный перечень поддерживаемых переменных этого файла:

| Переменная | Назначение, значение по умолчанию и пример |
|---|---|
| `NEO4J_URI` | Адрес Bolt, который используют Graphiti и прежний сервер Neo4j. По умолчанию `bolt://localhost:7687`; в контейнерных адресах `localhost`, `127.0.0.1` и `[::1]` заменяются на `host.docker.internal`. Пример удалённого сервера: `NEO4J_URI='bolt+s://neo4j.example.net:7687'`. Адрес должен быть доступен из соответствующих контейнеров. Он не отключает создание/запуск локального `neo4j-mcp`. |
| `NEO4J_USER` | Пользователь подключения Neo4j; по умолчанию `neo4j`. Пример: `NEO4J_USER=app_user`. Для нового локального контейнера установщик всегда задаёт начального пользователя `neo4j`; другой пользователь должен уже существовать в БД. |
| `NEO4J_USERNAME` | Альтернативное имя той же настройки, поддерживаемое скриптами и Graphiti. Если заданы оба имени, `NEO4J_USERNAME` имеет приоритет над `NEO4J_USER`. Для стандартного случая достаточно `NEO4J_USER`. |
| `NEO4J_PASSWORD` | Пароль подключения Neo4j; по умолчанию `mcp-neo4j-pass`. Это пароль нового контейнера Neo4j, создаваемого установщиком; он должен совпадать с паролем, который передаётся MCP-серверам. Укажите сильный пароль до первого запуска, например `NEO4J_PASSWORD='replace-with-a-long-random-secret'`. У уже существующего контейнера установщик пароль не меняет: при смене здесь отдельно измените пароль в самой БД и в интерфейсе MetaMCP. |
| `NEO4J_DATABASE` | Имя уже существующей базы Neo4j для Graphiti; по умолчанию `neo4j`. Пример: `NEO4J_DATABASE=knowledge`. Скрипт не создаёт указанную пользовательскую базу. Используйте отдельную базу/инстанс, если графы должны быть изолированы. Старый `neo4j-global` получает URI, имя пользователя и пароль, но не `NEO4J_DATABASE`. |
| `QDRANT_URL` | URL Qdrant для прежнего сервера `qdrant-global`; по умолчанию `http://localhost:6333`. Локальный адрес в контейнерном контексте превращается в `host.docker.internal`. Пример: `QDRANT_URL='https://qdrant.example.net:6333'`. Это значение не отключает создание/запуск локального `qdrant-mcp`. |
| `QDRANT_API_KEY` | Необязательный API-ключ Qdrant для прежнего сервера. Если пуст, поле не добавляется. Пример: `QDRANT_API_KEY='…'`. Не задаёт ключ на самом сервере Qdrant и не включает там аутентификацию автоматически. |
| `GITHUB_PERSONAL_ACCESS_TOKEN` | Токен, который при первоначальной регистрации задаётся как токен Bearer официального удалённого сервера `https://api.githubcopilot.com/mcp/`. Пример: `GITHUB_PERSONAL_ACCESS_TOKEN='github_pat_…'`. Можно оставить пустым и добавить токен в настройках сервера MetaMCP. Дайте токену только необходимые разрешения; переменная не создаёт доступ к GitHub и не обходит ограничения учётной записи/сервиса. |
| `CONTEXT7_API_KEY` | Необязательный ключ Context7. При первоначальной регистрации добавляется в окружение сервера `context7`; без него сервер работает с ограничениями исходного проекта. Пример: `CONTEXT7_API_KEY='…'`. |
| `APP_URL` | Публичный адрес источника (origin) MetaMCP, например `APP_URL=https://mcp.example.com`. При пустых обоих URL используется имеющаяся настройка MetaMCP; при непустом значении `run-global.sh start` переносит его в `~/mcp-global/metamcp/.env` и при необходимости пересоздаёт только приложение. Для применения без ожидания следующего старта используйте `apply-metamcp-config`. URL сам по себе не открывает порт в брандмауэре и не настраивает TLS или прокси; поддержка произвольного пути обратного прокси скриптом не настраивается. |
| `NEXT_PUBLIC_APP_URL` | Запасной источник публичного URL, если `APP_URL` пуст. Если заданы оба, приоритет у `APP_URL`. Синхронизация записывает выбранный URL в оба ключа MetaMCP `.env`; обычно задавайте только `APP_URL=https://mcp.example.com`. |
| `LLM_API_ENDPOINT` | Глобальный адрес API по умолчанию для LLM API; применяется, когда соответствующая переменная сервиса пуста. По умолчанию `https://api.openai.com/v1`. Пример: `LLM_API_ENDPOINT=https://llm.example/v1`. |
| `LLM_API_KEY` | Глобальный API-ключ по умолчанию для LLM API; применяется только если ключ конкретного сервиса пуст. Пример: `LLM_API_KEY='provider-key'`. Старый `OPENAI_API_KEY` вместо него не используется. |
| `LLM_API_MODEL` | Глобальная модель по умолчанию для LLM; применяется, если сервисная модель пуста. По умолчанию `gpt-4o-mini`. Пример: `LLM_API_MODEL=claude-3-5-sonnet`. |
| `LLM_API_PROVIDER` | Глобальный провайдер по умолчанию для поддерживающих его сервисов; сейчас используется Cognee, по умолчанию `openai`. Graphiti принимает адрес API, совместимый с OpenAI, и отдельный параметр провайдера не поддерживает. |
| `GRAPHITI_API_KEY` | API-ключ Graphiti; если пуст, используется `LLM_API_KEY`. Graphiti использует ключ для LLM и эмбеддингов. Пример: `GRAPHITI_API_KEY='graphiti-key'`. |
| `GRAPHITI_API_ENDPOINT` | Адрес API Graphiti; если пуст, используется `GRAPHITI_BASE_URL`, затем `LLM_API_ENDPOINT`, затем `https://api.openai.com/v1`. Передаётся контейнеру как `OPENAI_BASE_URL`. Пример: `GRAPHITI_API_ENDPOINT=https://graphiti.example/v1`. |
| `GRAPHITI_API_MODEL` | LLM-модель Graphiti; если пуст, используется `GRAPHITI_MODEL`, затем `LLM_API_MODEL`, затем `gpt-4o-mini`. Передаётся как `MODEL_NAME`. Пример: `GRAPHITI_API_MODEL=gpt-4o-mini`. |
| `GRAPHITI_EMBEDDER_MODEL` | Модель эмбеддингов Graphiti; по умолчанию `text-embedding-3-small`. Передаётся как `EMBEDDER_MODEL`. Пример: `GRAPHITI_EMBEDDER_MODEL=text-embedding-3-small`. Модель и её размерность должны поддерживаться конфигурацией Graphiti. |
| `GRAPHITI_GROUP_ID` | Идентификатор группы Graphiti, по умолчанию `multfinite-mcp-kit-global`. Определяет группировку/изоляцию данных внутри Graphiti. Пример: `GRAPHITI_GROUP_ID=team-knowledge`. Используйте одинаковое значение для клиентов, которым нужен общий граф; изменение не переносит уже записанные данные. |
| `COGNEE_LLM_API_PROVIDER` | Провайдер языковой модели Cognee; если пуст, используется `COGNEE_LLM_PROVIDER`, затем `LLM_API_PROVIDER`, затем `openai`. Выберите поддерживаемое Cognee значение. |
| `COGNEE_LLM_API_KEY` | API-ключ только для LLM Cognee; если пуст, используется `LLM_API_KEY`. Пример: `COGNEE_LLM_API_KEY='cognee-llm-key'`. |
| `COGNEE_LLM_API_MODEL` | Модель LLM Cognee; если пуст, используется `COGNEE_LLM_MODEL`, затем `LLM_API_MODEL`, затем `gpt-4o-mini`. Пример: `COGNEE_LLM_API_MODEL=gpt-4o-mini`. |
| `COGNEE_LLM_API_ENDPOINT` | Адрес API LLM Cognee; если пуст, используется `COGNEE_LLM_ENDPOINT`, затем `LLM_API_ENDPOINT`, затем `https://api.openai.com/v1`. Передаётся как `LLM_ENDPOINT`. Пример: `COGNEE_LLM_API_ENDPOINT=https://llm.example/v1`. Согласуйте провайдера, модель и адрес API с Cognee/LiteLLM. |
| `COGNEE_EMBEDDING_API_PROVIDER` | Провайдер эмбеддингов Cognee; созданный файл задаёт `openai`. Если пуст, используется `COGNEE_EMBEDDING_PROVIDER`, затем `LLM_API_PROVIDER`, затем `openai`. Должен поддерживаться Cognee. |
| `COGNEE_EMBEDDING_API_KEY` | API-ключ эмбеддингов Cognee; если пуст, используется глобальный `LLM_API_KEY`. Пример: `COGNEE_EMBEDDING_API_KEY='embedding-key'`. |
| `COGNEE_EMBEDDING_API_ENDPOINT` | Адрес API эмбеддингов Cognee; если пуст, используется `COGNEE_EMBEDDING_ENDPOINT`, затем `LLM_API_ENDPOINT`, затем `https://api.openai.com/v1`. Передаётся как `EMBEDDING_ENDPOINT`. Пример: `COGNEE_EMBEDDING_API_ENDPOINT=https://embeddings.example/v1`. |
| `COGNEE_EMBEDDING_API_MODEL` | Модель эмбеддингов Cognee; созданный файл задаёт `text-embedding-3-small`. Если значение пусто, используется `COGNEE_EMBEDDING_MODEL`, затем то же встроенное значение по умолчанию. Модель и размерность должны соответствовать адресу API. |
| `COGNEE_EMBEDDING_DIMENSIONS` | Размерность вектора Cognee; по умолчанию `1536`. Пример: `COGNEE_EMBEDDING_DIMENSIONS=1536`. Укажите число, которое соответствует выбранной модели эмбеддингов/провайдеру и уже созданным данным. Несоответствие модели и размерности может ломать индексацию и поиск. |

После изменения переменных Graphiti/Cognee примените изменения командой:

```sh
bash linux/run-global.sh apply-services
```

Она пересоздаёт только контейнеры Graphiti и Cognee, сохраняет их именованные тома и не меняет настройки серверов MetaMCP. Заранее сохраните ручные файлы из записываемого слоя этих контейнеров. При обычном `start` комплект также проверяет доступ на запись пользователя MetaMCP к именованному тому кэша uv; если том был создан со старым владельцем root, владельцем файлов становится uid/gid `1001:1001` (пользователь `nextjs`), приложение остаётся непривилегированным. После запуска вспомогательных сервисов комплекта и подключения Docker-сетей `start` сбрасывает `Error Status` только у общих записей с именами `neo4j-global`, `qdrant-global`, `fetch`, `duckduckgo`, `graphiti`, `cognee`, `memory-bank-mcp`, `gdrive`, чтобы старые версии MetaMCP повторили соединение после временной ошибки запуска. Проверки происхождения записи при этом нет: ранее существовавшая общая запись с таким именем тоже затрагивается. Конфигурации записей не меняются. Секреты GitHub, Context7 и параметры Neo4j/Qdrant, передаваемые при первоначальной регистрации, не обновляются повторным обычным `start`: существующие записи MetaMCP намеренно не перезаписываются. Измените такие серверы через интерфейс MetaMCP либо отдельно выполните `bash linux/run-global.sh seed` после проверки поведения регистрации; команда добавляет отсутствующие записи, но не обновляет имеющиеся.

Команда `bash linux/run-global.sh start` автоматически синхронизирует непустые `APP_URL` / `NEXT_PUBLIC_APP_URL` из этого `.env` в файл исходного проекта `~/mcp-global/metamcp/.env`. MetaMCP Compose читает этот расположенный на хосте `.env` через `env_file` и передаёт URL как переменные окружения контейнера; официальный образ не содержит отдельного `.env` внутри контейнера. Скрипт сверяет значения с окружением контейнера приложения и пересоздаёт только `app`, если там URL устарели, затем ждёт проверки работоспособности и подключает сети вспомогательных сервисов заново. Чтобы синхронизировать URL отдельно, не дожидаясь следующего `start`, выполните `bash linux/run-global.sh apply-metamcp-config`. **Перед запуском сохраните ручные файлы из записываемого слоя контейнера приложения**; тома Compose не удаляются. Для внешнего доступа отдельно настройте DNS, достижимость порта, TLS (обычно обратный прокси) и брандмауэр; не передавайте ключи по незащищённой сети. `APP_URL` сам по себе не публикует приложение в интернет.

> **Важно для первого запуска Neo4j.** Задайте `NEO4J_PASSWORD` до `install-global.sh`, создав `~/mcp-global/config/.env` вручную (папку можно создать заранее). Установщик создаёт `neo4j-mcp` только если такого контейнера ещё нет. Для уже созданного контейнера изменение `.env` не меняет пароль и не пересоздаёт контейнер.

#### Как значения попадают в контейнеры и MetaMCP

| Источник `.env` | Получатель |
|---|---|
| `LLM_API_*`, `GRAPHITI_API_*`, `GRAPHITI_EMBEDDER_MODEL`, `GRAPHITI_GROUP_ID`, настройки Neo4j | Контейнер `mcpkit-graphiti`; выбранные адрес API и ключ отображаются в `OPENAI_BASE_URL` и `OPENAI_API_KEY`, модели LLM и эмбеддингов — в `MODEL_NAME` и `EMBEDDER_MODEL`. Непустые `GRAPHITI_API_*` имеют приоритет над глобальными `LLM_API_*`. |
| `COGNEE_LLM_API_*`, `COGNEE_EMBEDDING_API_*`, `COGNEE_EMBEDDING_DIMENSIONS` | Контейнер `mcpkit-cognee`; LLM-настройки отображаются в `LLM_*`, настройки эмбеддингов — в `EMBEDDING_*`, включая `EMBEDDING_ENDPOINT`. Для каждого набора непустые сервисные значения переопределяют глобальные значения API по умолчанию. Постоянные файлы Cognee находятся в отдельных томах. |
| `APP_URL`, `NEXT_PUBLIC_APP_URL` | При `start` или `apply-metamcp-config` синхронизируются в одноимённые ключи `~/mcp-global/metamcp/.env`; если URL изменился, приложение пересоздаётся, чтобы Compose передал обновлённое окружение. |
| `NEO4J_URI`, пользователь, пароль | Запись прежнего сервера `neo4j-global` в MetaMCP как `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`. |
| `QDRANT_URL`, `QDRANT_API_KEY` | Запись прежнего сервера `qdrant-global` как `QDRANT_URL`, `QDRANT_API_KEY` (пустой ключ опускается). |
| `GITHUB_PERSONAL_ACCESS_TOKEN` | Токен Bearer удалённого сервера `github-mcp-server`. |
| `CONTEXT7_API_KEY` | Переменная окружения `CONTEXT7_API_KEY` сервера `context7`. |

MetaMCP подключается к Graphiti, Cognee, Memory Bank и GDrive по внутренним Docker DNS-именам и порту `8000`; наружу их порты не публикуются. Их адреса и другие свойства регистрации задаются скриптом регистрации, а не `.env`.

### MetaMCP: `~/mcp-global/metamcp/.env`

Это отдельный `.env` самого исходного приложения MetaMCP, а не файл API-ключей набора. Он создаётся копированием `${HOME}/mcp-global/metamcp/example.env`, если отсутствует. При создании установщик задаёт права `600` и генерирует секреты; существующий файл этот шаг не заменяет. Последующий `start` может синхронизировать в нём URL. Compose MetaMCP читает этот файл.

Linux-установщик выполняет `git clone --depth 1` **ветки по умолчанию** исходного MetaMCP без закрепления коммита. Если каталог уже содержит `.git`, он используется без `git pull`; установщик также пытается выполнить `docker compose pull`. Ниже приведены изменения, которые вносит комплект, и справочные примеры переменных из одного снимка исходного `example.env`. Имена, значения по умолчанию и логика исходного проекта могут отличаться: для вашей установки сверяйтесь с её `~/mcp-global/metamcp/example.env`, Compose и версией образа.

| Переменная / ключ | Назначение и пример |
|---|---|
| `APP_URL` | Публичный базовый URL MetaMCP, используемый сервером для ссылок. При первом создании исходного файла `.env` берётся из `~/mcp-global/config/.env`; иначе исходное значение `http://localhost:12008`. Для внешнего доступа укажите, например, `APP_URL=https://mcp.example.com`; `run-global.sh start` синхронизирует его автоматически, а `apply-metamcp-config` применяет немедленно. |

#### JSON-ключи внутри `BOOTSTRAP_*`

Значения `BOOTSTRAP_API_KEYS`, `BOOTSTRAP_NAMESPACES`, `BOOTSTRAP_ENDPOINTS` и `BOOTSTRAP_USERS` должны быть корректным JSON в одной строке `.env`. Для длинных значений используйте кавычки/экранирование, совместимые с синтаксисом dotenv и Compose, либо применяйте интерфейс MetaMCP вместо bootstrap. Ключи объектов:

| Объект / ключ | Значение |
|---|---|
| Пользователь (`BOOTSTRAP_USERS`) — `email`, `password` | Обязательные адрес и пароль. |
| Пользователь — `name` | Необязательное отображаемое имя. |
| API-ключ (`BOOTSTRAP_API_KEYS`) — `name` | Обязательное имя ключа. |
| API-ключ — `is_public` | `true` для общего ключа, `false` для пользовательского; значение по умолчанию в исходном проекте — `false`. Общий ключ даёт доступ в пределах конфигурации конечной точки; защищайте его как секрет. |
| API-ключ — `user_email` или `owner` | Необязательный адрес владельца пользовательского ключа; `owner` — алиас `user_email`. Если не задан, исходный проект использует первого пользователя. |
| Пространство имён (`BOOTSTRAP_NAMESPACES`) — `name` | Обязательное имя пространства имён. |
| Пространство имён — `description` | Необязательное описание. |
| Пространство имён — `is_public` | Общее пространство (`true`) или пользовательское (`false`); значение по умолчанию в исходном проекте — `false`. |
| Пространство имён — `user_email` или `owner` | Необязательный адрес владельца пользовательского пространства; `owner` — алиас `user_email`. |
| Пространство имён — `update` | Обновлять ли существующее пространство с таким именем; значение по умолчанию в исходном проекте — `true`. Установщик меняет буквальное `"update":true` на `"update":false`, чтобы не перезаписывать существующие записи. |
| Конечная точка (`BOOTSTRAP_ENDPOINTS`) — `name` | Обязательное имя конечной точки. |
| Конечная точка — `description` | Необязательное описание. |
| Конечная точка — `enable_auth` | Включает аутентификацию по API-ключу; значение по умолчанию в исходном проекте — `true`. Не отключайте на публично доступной конечной точке. |
| Конечная точка — `enable_auth_query` | Разрешает передачу ключа в строке запроса; значение по умолчанию — `false`, требуется `enable_auth=true`. Строка запроса может попадать в историю и логи, поэтому предпочтительнее заголовок Authorization. |
| Конечная точка — `enable_auth_oauth` | Включает аутентификацию OAuth; значение по умолчанию — `false`. Это отдельная возможность от аутентификации по API-ключу. |
| Конечная точка — `is_public` | Общая конечная точка (`true`) либо принадлежащая пользователю (`false`); значение по умолчанию в исходном проекте — `true`. |
| Конечная точка — `user_email` или `owner` | Необязательный владелец пользовательской конечной точки; `owner` — алиас `user_email`. |
| Конечная точка — `namespace` | Пространство имён, в котором создаётся конечная точка; если не задано, исходный проект выбирает первое доступное. Указывайте имя существующего пространства. |
| Конечная точка — `update` | Обновлять ли существующую конечную точку; значение по умолчанию в исходном проекте — `true`. Установщик меняет буквальное `"update":true` на `"update":false`. |

Параметр `BOOTSTRAP_API_KEYS` в использованном снимке исходного шаблона содержит JSON-массив `[{"name":"Public","is_public":true},{"name":"Private","is_public":false}]`; его объекты и ключи описаны в таблице выше. Установщик проекта не меняет этот массив. Bootstrap-конфиг MetaMCP и записи, которые отдельно добавляет `seed-global.sql`, — разные механизмы; сверяйте имена конечных точек и пространств имён, чтобы не создавать конфликты или неосознанно открытые конечные точки.

При первом создании MetaMCP `.env` установщик берёт публичный адрес источника (origin) из `APP_URL` (или из `NEXT_PUBLIC_APP_URL`, если `APP_URL` пуст) в конфигурационном файле комплекта `.env` и записывает его в оба ключа. Если ни один адрес не задан, он подставляет `http://localhost:12008`. Установщик генерирует `BETTER_AUTH_SECRET` и пароль PostgreSQL, очищает одиночные `BOOTSTRAP_USER_EMAIL`/`BOOTSTRAP_USER_PASSWORD`, устанавливает `BOOTSTRAP_RECREATE_USER=false` и заменяет только буквальное `"update":true` на `"update":false` в строках пространств имён и конечных точек bootstrap. Эти замены действуют только на соответствующие строки, уже присутствующие в исходном шаблоне. Он не отключает bootstrap и не очищает, например, `BOOTSTRAP_USERS`. Проверьте фактический шаблон и настройки регистрации: bootstrap может снова применить настройки регистрации при перезапуске. Закройте ненужную UI/SSO-регистрацию и защитите права администраторов до публикации. Уже существующий MetaMCP `.env` установщик не изменяет, но последующий `start` может синхронизировать в нём URL.

При ручном изменении `.env` одного редактирования может быть недостаточно: `run-global.sh start` запускает MetaMCP с `docker compose up -d --no-recreate`, чтобы не уничтожать конфигурацию существующего контейнера. Для применения изменений следуйте процедуре MetaMCP/Compose и заранее сохраните ручные данные контейнера. Не удаляйте контейнер и не запускайте `down -v`, если не хотите потерять данные.

### Linux: переменная запуска

`METAMCP_START_TIMEOUT` — переменная окружения процесса для ожидания готовности MetaMCP и завершения миграций, в секундах; по умолчанию `180`. Пример: `METAMCP_START_TIMEOUT=300 bash linux/run-global.sh start`. Допустимы от одной до семи десятичных цифр, включая `0`; другие значения вызывают ошибку. Она не читается из `~/mcp-global/config/.env`.

### Linux: низкоуровневая регистрация Windows-шлюза

В репозитории есть отдельный `linux/register-local.sh --stdin [--force]` для уже работающего Linux GLOBAL MetaMCP. Это не часть обычного Windows `start`: текущий управляющий скрипт Windows **не экспортирует регистрационный пакет и не настраивает SSH, TLS, VPN, маршрутизацию или брандмауэр**. Поэтому команда сама по себе не создаёт готовое соединение между компьютерами. Используйте её только при самостоятельно настроенном и проверенном защищённом маршруте; стандартная Windows LOCAL установка регистрирует серверы в своём локальном Docker MetaMCP.

Регистратор требует `jq`, доступный Docker, работающее приложение и `~/mcp-global/metamcp/.env`. Он читает один JSON-объект из stdin (не более 16384 символов):

| Поле пакета | Требование |
|---|---|
| `version` | Число `1`. |
| `hostId` | Непустые строчные латинские буквы/цифры, разделённые одиночными `-`; до 32 символов. |
| `ownerEmail` | Email единственной уже существующей учётной записи Linux MetaMCP; поиск без учёта регистра. |
| `baseUrl` | URL шлюза без завершающего `/`, строки запроса и фрагмента; `http` или `https`, имя хоста/IPv4 и необязательные порт и путь. Буквальный IPv6-адрес и `..` не принимаются. |
| `gatewayKey` | Секрет шлюза из 64 строчных шестнадцатеричных символов. Он записывается в заголовки создаваемых серверов в БД MetaMCP. |
| `allowInsecureLan` | Логическое значение. Для HTTP вне `localhost`/`127.0.0.1` обязательно `true`, но этот флаг **не шифрует** связь; нужен отдельно защищённый туннель или VPN. |

`baseUrl` должен быть доступен из контейнера приложения MetaMCP. Поведение адресов `localhost` и их возможное преобразование в `host.docker.internal` зависит от конфигурации исходного проекта; не считайте Windows loopback автоматически доступным с другой машины или из контейнера.

Пакет содержит секрет: передавайте его по защищённому каналу через stdin, не помещайте ключ в аргументы, историю команд, Git или логи. Скрипт создаёт приватные записи владельца: пространство имён и конечную точку `local-<hostId>` и серверы `local-<hostId>-<server-id>`. Новая конечная точка требует API-ключ; при выполнении регистрации открытая или чужая конечная точка в целевом пространстве имён либо совпадение имени конечной точки с чужой записью вызывает откат транзакции. Повторный запуск без `--force` при наличии маркера сохраняет удаления и не перепроверяет последующие изменения авторизации; явный `--force` добавляет недостающие записи по умолчанию, но не перезаписывает несовместимые подключения и не включает отключённые сопоставления. Это отдельный механизм от общих групп Windows LOCAL и от `run-local.ps1 seed`.

### Windows LOCAL: настройки и секреты

Стандартный путь — `%USERPROFILE%\mcp-local`; `$env:MCP_LOCAL_DIR` задаёт альтернативный базовый путь. Используйте одно и то же значение во всех установочных и управляющих командах. Нужны Windows 10/11 x64, 64-битный PowerShell 5.1+, интерактивная пользовательская сессия и Docker Desktop с контейнерами Linux и Compose не ниже `2.24.4`. Управляющий скрипт явно использует только локальный контекст `desktop-linux` и проверяет его именованный канал, а не текущий или удалённый контекст Docker. Оба варианта установки запускают MetaMCP **на этом Windows-компьютере**, а не подключаются по SSH к Linux.

#### Параметры установщика

Команды выполняются из корня репозитория. Полная установка — `.\windows\install-local.ps1`; параметры можно сочетать:

| Параметр | Действие |
|---|---|
| `-MetaMcpOnly` | Для уже инициализированного LOCAL с `config\local-settings.json`, `config\private\secrets.json` и пакетами среды выполнения: проверяет Git/Docker и запускает существующий шлюз и локальный MetaMCP, не переустанавливая нативные пакеты. Если есть только старые `.env`/`mcp-local.json`, нужна полная установка. Остальные параметры установки серверов в этом режиме не применяются. |
| `-NonInteractive` | Не задаёт вопрос об установке C++ Build Tools. Если они отсутствуют и `-InstallBuildTools` не указан, установка группы vectorstore сообщает ошибку; возможны системные запросы WinGet/UAC и настройки Docker/WSL. |
| `-InstallBuildTools` | Разрешает установить отсутствующий компонент Visual C++ Build Tools через WinGet; загрузка может занять несколько гигабайт. |
| `-SkipEverything` | Пропускает установку/запуск Everything и загрузку SDK; серверу нужны существующие приложение, индекс и DLL. |
| `-SkipBrowserDownload` | Пропускает загрузку Chromium, но не установку пакета Playwright; браузер должен быть доступен отдельно. |

Для отсутствующих Git, Docker Desktop, начального Node, Everything и при согласии C++ Build Tools используется WinGet. Изолированные Node/npm при создании задаются версиями из `windows/manifest.json` (сейчас `24.22.3`/`11.11.1`); уже существующая среда выполнения комплекта не заменяется и проверяется как Node 24 x64. Для Python используется имеющийся `uv` версии не ниже `0.9.0` либо закреплённый и проверяемый по SHA-256 пакет wheel комплекта (сейчас `0.13.8`). Скрипт использует/устанавливает x64 Python `3.12` для большинства серверов и `3.14` для Windows-MCP, создаёт отдельные виртуальные окружения и устанавливает закреплённые пакеты из манифеста. Python-интерпретаторы могут находиться вне каталога комплекта. Установщик может сообщить неполную установку и вернуть ошибку, но всё равно попытаться запустить остальные серверы и MetaMCP.

| `$env:MCPKIT_DOCKER_START_TIMEOUT` | Ожидание Docker Desktop в секундах; значение по умолчанию `120`. Принимаются 1–3 цифры, после чего число ограничивается диапазоном `1–600`; некорректное значение игнорируется. |
| `$env:MCPKIT_METAMCP_START_TIMEOUT` | Аналогичное ожидание готовности MetaMCP; значение по умолчанию `240`, правило 1–3 цифр и диапазон `1–600` те же. |

#### Поля `local-settings.json` и `secrets.json`

Ниже — значения при создании без подходящей старой конфигурации; существующие файлы не заменяются. Пути JSON должны быть абсолютными и содержать удвоенные обратные слеши, например `C:\\Users\\name\\projects`.

| Поле | Начальное значение и ограничения |
|---|---|
| `version` | Число `1`. |
| `hostId` | Имя компьютера, приведённое к нижнему регистру и сокращённое до 20 символов, плюс случайный суффикс из 6 hex-символов; допускаются строчные латинские буквы, цифры и одиночные дефисы, всего до 32 символов. Идентификатор привязан к регистрации: не меняйте его на существующей установке без анализа последствий. |
| `listenHost` | `127.0.0.1`. `localhost` также разрешён для автоматического Docker-маршрута; IPv6 loopback и TLS в нём не поддерживаются. |
| `port` | Порт шлюза `13001`, целое число `1–65535`. Он должен отличаться от портов MetaMCP. |
| `tlsCertFile`, `tlsKeyFile` | Пустые строки. Для TLS шлюза указываются **оба** абсолютных пути к существующим файлам; сертификат должен быть PEM. Это настройки шлюза, не TLS MetaMCP; автоматическая локальная Docker-регистрация требует HTTP без TLS. |
| `allowInsecureLan` | `false`. Прослушивание нелокального адреса без TLS запрещено, если явно не установить `true`. Сам флаг не включает шифрование, VPN или брандмауэр; не открывайте шлюз в ненадёжную сеть. |
| `projectsDir`, `writingDir` | `<base>\data\projects` и `<base>\data\writing`; `init` создаёт эти каталоги по умолчанию. `filesystem` использует оба, CodeGraph — `projectsDir`, vectorstore — `writingDir`. Создайте собственные каталоги до запуска: отсутствующие пути переводят соответствующие серверы в `waiting`. |
| `everythingSdkPath` | `<base>\runtime\everything-sdk\Everything64.dll`; при отсутствии DLL Everything-сервер ждёт настройки. Если указан другой отсутствующий путь, установщик не заменяет его автоматически. |
| `obsidianHost`, `obsidianPort` | `127.0.0.1`, `27124`; допустимы только `127.0.0.1` или `localhost` и порт `1–65535`. Сервер обращается к Local REST API по HTTPS, но сторонний клиент не проверяет сертификат; для удалённого API нужен локально завершающийся защищённый туннель. |
| `gatewayApiKey` | Случайный секрет из 64 строчных hex-символов. Используется в `X-API-Key` при прямом доступе к `/servers/<server-id>/mcp`, отдельно от API-ключа MetaMCP. Один ключ даёт доступ ко всем серверам шлюза. |
| `obsidianApiKey` | Пустая строка; задайте ключ плагина Local REST API, иначе Obsidian остаётся в `waiting`. |
| `dbhubDsn` | Пустая строка; DBHub использует SQLite `data\dbhub.sqlite`. Непустая строка передаётся DBHub как DSN и может содержать секреты. |

При первом создании каждого JSON-файла скрипт буквально читает из старого `config\.env` валидные `PROJECTS_DIR`, `WRITING_DIR`, `DBHUB_DSN` и `OBSIDIAN_API_KEY`: пути импортируются только если они абсолютные и каталоги существуют, очевидный пример DSN не импортируется. Старые `config\.env` и `config\mcp-local.json` не изменяются и затем не обновляют действующие настройки. Для изменений каталогов, Obsidian или DBHub сохраните JSON и выполните `restart`: уже работающий шлюз не перечитывает настройки. Изменение `hostId`, порта или `gatewayApiKey` не синхронизирует существующие подключения в MetaMCP автоматически; перед таким изменением проверьте и согласуйте записи, а при утрате ключа восстановите его из резервной копии, не генерируя новый вслепую.

Шлюз разрешает отдельное защищённое прослушивание, но это не готовая схема удалённого подключения MetaMCP. Для стандартной регистрации Docker Desktop значение `listenHost` должно быть равно `127.0.0.1` или `localhost`, а TLS-пути должны быть пустыми. Скрипт не меняет брандмауэр и не расширяет прослушиваемый адрес при ошибке `host.docker.internal`.

Проверить и изменить порты существующей установки:

```powershell
.\windows\run-local.ps1 ports
.\windows\run-local.ps1 set-ports -WebPort 13008 -BackendPort 13009
```

Внешняя часть обслуживает интерфейс и конечные точки MCP; серверная часть напрямую доступна только на loopback и не нужна для обычного подключения. В старом состоянии без `backendPort` управляющий скрипт использует `0` и сохраняет прежний порт интерфейса. `WebPort` — `1–65535`, `BackendPort` — `0–65535`, причём ненулевой порт серверной части должен отличаться от порта интерфейса и оба — от порта шлюза; порты должны быть свободны. Чтобы не публиковать серверную часть, укажите `-BackendPort 0`. Команда `set-ports` требует оба параметра и затем запускает полный стек, даже если порты уже совпадают. Порты внутри контейнера остаются 12008/12009. `port` в `local-settings.json` — отдельный порт шлюза Windows, а не MetaMCP.

При создании установки скрипт клонирует ревизию исходного MetaMCP из `windows/manifest.json` (сейчас `05818ec2767b946f98d280ae9cefa401f0362d62`) и собирает её в отдельный образ; существующий посторонний каталог `metamcp` не используется и не меняется. Уже созданный управляемый клон или сохранённый образ обычным запуском не обновляется. Отдельный Compose-проект хранит PostgreSQL и кэш в собственных томах. Обычный `start` применяет `--no-recreate`, `stop` не удаляет контейнеры и тома. Для изменения портов, обновления старой bootstrap-конфигурации или добавления администратора может потребоваться пересоздать только контейнер приложения: скрипт сохраняет его записываемый слой в локальном Docker-образе и запускает новый контейнер из него. Образ может содержать секреты; не публикуйте его. Само пересоздание не удаляет базу, тома или существующие пароли; другие этапы `start` и `seed` могут менять записи БД по правилам ниже. Сохранённые ожидающие изменения конфигурации повторяются при `start`. Интерфейс и серверная часть доступны только через `127.0.0.1`, PostgreSQL не публикуется.

При первом `start` на чистой установке без конфликтов автоматически создаются 13 общих (public) серверов с короткими именами, например `filesystem` и `git`, и общие пространства имён и конечные точки `system`, `files`, `code`, `web`, `data`, `memory` с разделением по темам и точными именами серверов из README. Для этого учётная запись не нужна. Новые конечные точки требуют API-ключ; стандартный интерфейс остаётся на loopback. Общедоступность означает видимость всем пользователям MetaMCP, а не анонимный или сетевой доступ. В закреплённой версии любой действующий личный или общий API-ключ проходит проверку для общих конечных точек с включённой авторизацией по API-ключу; выбор одного URL не ограничивает доступ к остальным группам. Инструменты могут изменять файлы и управлять рабочим столом, поэтому выдавайте ключи только доверенным клиентам. При успешном запуске скрипт выводит доступные URL `/metamcp/<endpoint>/mcp`; SSE доступен по `/sse`. Проверьте предупреждения и фактическую авторизацию существующих конечных точек в интерфейсе.

Учётную запись пользователь создаёт в интерфейсе самостоятельно. Механизм bootstrap исходного MetaMCP отключён, поэтому он не создаёт пользователей и не сбрасывает выбранную в интерфейсе настройку регистрации при перезапуске. Само отключение bootstrap **не открывает** ранее закрытую регистрацию: при необходимости используйте `enable-signup`. В **Настройки → Настройки авторизации** вручную отключите регистрацию через форму и при необходимости через SSO; в разделе **Ключи API (API Keys)** самостоятельно создайте личный ключ. Ключ Windows-шлюза не совпадает с клиентским ключом MetaMCP. При пустом списке администраторов исходный MetaMCP считает администратором любого вошедшего пользователя; закройте регистрацию сразу после создания нужных учётных записей.

На старой установке `start` отключает ещё действующий bootstrap без изменения состояния регистрации и учётных записей. Если регистрация закрыта, её можно явно открыть командой `enable-signup`. Миграция V3 переиспользует старые серверы V1 и устраняет совместимые дубликаты V2, по возможности сохраняя UUID, подключения, сопоставления, настройки инструментов, OAuth-сессию и аудит. Перевод прежних приватных записей в общие меняет их видимость и доступ для пользователей MetaMCP, даже при сохранённой аутентификации; перед обновлением проверьте допустимость такого доступа. Старая конечная точка и пространство имён остаются с прежними UUID и URL и безопасно переводятся в общие; при конфликтах или дополнительных чужих серверах перевод откладывается. Различающиеся соединения, схемы инструментов и ограничения, несколько OAuth-сессий, чужие имена и неизвестные ссылки БД не удаляются автоматически; выводится предупреждение, и соответствующие дубликаты могут остаться до ручного разрешения конфликта. Если в целевом пространстве имён есть открытая конечная точка, новые инструменты туда не добавляются; уже существующие сопоставления могут быть доступны без ключа. Чужое или заменённое пространство имён не используется даже по явной команде `seed`.

Для первой регистрации, применения миграции и при каждом явном `seed` скрипт останавливает только приложение, делает `pg_dump` в `mcpkit-backups` внутри тома PostgreSQL и запускает тот же контейнер приложения: это сбрасывает старые активные и подготовленные MCP-сессии без пересоздания контейнера. Дамп содержит секреты и не является независимой копией тома — храните отдельную защищённую резервную копию. При ошибке резервного копирования миграция БД не применяется. Переименование меняет имена MCP-инструментов (например, на `filesystem__...`), даже если URL старой конечной точки тот же: переподключите клиентов и обновите их список разрешённых инструментов. Повторный обычный `start` без новой миграции не делает новый дамп и не восстанавливает удалённые записи. Явный `seed` после проверки предупреждений может восстановить удалённые записи по умолчанию, но не перезаписывает существующие подключения или отключённые сопоставления; при безопасной миграции имена и видимость записей могут измениться.

На старой установке группы с именами `local-<hostId>-...` сохраняются при обычном `start`. Отдельная команда `reset-metamcp-records` по подтверждению `DELETE ALL LOCAL RECORDS` удаляет **все** серверы, пространства имён и конечные точки этой Windows-базы, включая ручные, и в той же транзакции создаёт 13 серверов и шесть защищённых групп с короткими именами. Удаляются их настройки инструментов, сопоставления и серверные OAuth-сессии; ссылки аудита на удалённые записи очищаются. Учётные записи, API-ключи MetaMCP, регистрация, файлы Windows-серверов, другие базы и тома сохраняются. Перед сбросом создайте независимую защищённую копию; автоматический `pg_dump` внутри того же тома содержит секреты и не является такой копией. При неизвестных внешних ссылках или триггерах сброс блокируется. Он не вызывается при обычном `start` или `seed`; повторный явный вызов снова удалит записи. При неопределённом результате или ошибке перезапуска не повторяйте сброс вслепую — запустите `start` и проверьте MetaMCP и резервную копию.

Новый управляющий скрипт до удаления проверяет в `windows\seed-local.sql` метку совместимости `MCPKIT_RESET_CONTRACT: short-names-v4` и выводит каталог используемых скриптов. Это не проверка целостности локальных правок, а старый скрипт такой проверки не делает. Если после сброса остались префиксы, сначала проверьте HEAD, состояние рабочих файлов и текущие имена в интерфейсе без повторного сброса; команды диагностики приведены в README.

В обычном случае `-OwnerEmail` не нужен даже при нескольких учётных записях. Если на старой установке есть список администраторов и новому пользователю нужны права администратора, после регистрации и проверки предупреждений используйте `seed -OwnerEmail 'you@example.com'`: эта команда одновременно выполняет явный `seed` и добавляет выбранного существующего пользователя к прежнему списку администраторов. Данные и права Docker, ACL Windows и резервные копии БД необходимо защищать: серверы могут выполнять команды, управлять рабочим столом и изменять файлы.

#### Команды Windows LOCAL

Вызов из корня: `.\windows\run-local.ps1 <команда> [параметры]`; без команды выполняется `start`.

| Команда | Действие |
|---|---|
| `init` | Создаёт каталоги и отсутствующие JSON-настройки/секреты, не заменяя имеющиеся. Вызывается полной установкой; сама по себе не устанавливает пакеты и MetaMCP. |
| `start` | Пытается запустить шлюз и затем Docker MetaMCP, при необходимости выполняет автоматическую регистрацию или миграцию и проверяет мост подключения. При частичном отказе возвращает ошибку, даже если часть стека запущена. |
| `stop` / `restart` | Останавливает шлюз и только контейнеры MetaMCP, принадлежащие комплекту; `restart` затем запускает стек. Контейнеры и тома не удаляются. Для остановки не запускает выключенный Docker Desktop; если он недоступен, остановка контейнеров не подтверждена. |
| `status` | Показывает состояние шлюза и Docker-проекта, проверяет связь с ним. `error` или оставшийся `starting` дают ошибку, `waiting` само по себе — нет. |
| `logs [имя]` | Последние 100 строк доступных журналов; имя — `gateway`, `metamcp` или ID сервера из `windows/manifest.json`, например `codebase-memory-mcp`. Без имени показывает шлюз и нативные серверы, **не** журнал MetaMCP. Вывод не следует за новыми строками. |
| `credentials` | Только для распознаваемой старой bootstrap-учётной записи показывает исходные email и пароль; пароль может быть уже изменён. Новую учётную запись не создаёт. Вывод содержит секрет. |
| `seed [-OwnerEmail 'email']` | Явно повторяет консервативную регистрацию/миграцию: нужен уже работающий MetaMCP без ожидающих изменений. Останавливает приложение, делает внутренний дамп и добавляет недостающее по правилам выше. Не удаляет все записи. `-OwnerEmail` разрешён только с `seed`, указывает существующую однозначную учётную запись и при непустом старом списке администраторов добавляет её к нему. |
| `reset-metamcp-records` | Отдельно подтверждаемый **полный разрушительный сброс** записей Windows MetaMCP; см. предупреждения и резервное копирование выше и в README. |
| `enable-signup` | Явно включает только регистрацию через интерфейс в уже запущенном MetaMCP без ожидающих изменений. SSO и учётные записи не меняются; закройте регистрацию самостоятельно после использования. |
| `ports` | Показывает сохранённые порты или значения по умолчанию до создания установки; не меняет их. |
| `set-ports -WebPort <порт> -BackendPort <порт-или-0>` | Сохраняет оба порта существующей установки и запускает полный стек; может пересоздать только приложение с предварительным сохранением его слоя. |
| `gateway-start`, `gateway-stop`, `gateway-restart`, `gateway-status` | Управляют только шлюзом и его дочерними нативными серверами; Docker MetaMCP и его записи эти команды не запускают и не меняют. |

`ready` подтверждает ответ MCP на `initialize`, но не проверяет все операции, индекс Everything, модель или права рабочего стола. Изменения внешних данных и секретов см. в [разделе восстановления README](../README.md#обновление-и-восстановление). После аварии не удаляйте файлы состояния и не завершайте неизвестные процессы; файл блокировки можно убрать лишь после проверки, что операция не выполняется.

## `linux/services/docker-compose.yml`

Это Compose-описание четырёх вспомогательных контейнеров набора. Оно настраивается через `~/mcp-global/config/.env` и `linux/run-global.sh`, а не через `.env` MetaMCP. `MCPKIT_*` — промежуточные переменные окружения, которые формирует `run-global.sh`; вручную задавать их обычно не нужно. Внутренние переменные `MCPKIT_*` соответствуют глобальным `LLM_API_*`, сервисным `MCPKIT_GRAPHITI_API_*`, `MCPKIT_COGNEE_LLM_API_*`, `MCPKIT_COGNEE_EMBEDDING_API_*` и дополнительным настройкам Neo4j, Graphiti и размерности эмбеддингов. Их значения и соответствия переменным контейнеров указаны в таблицах Linux `.env` выше.

| Сервис | Внутренний адрес, используемый MetaMCP | Настройки контейнера |
|---|---|---|
| `mcpkit-graphiti` | `http://mcpkit-graphiti:8000/mcp` | `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`, `NEO4J_DATABASE`; `OPENAI_API_KEY`, `OPENAI_BASE_URL`; `MODEL_NAME`, `EMBEDDER_MODEL`, `GRAPHITI_GROUP_ID`. Настройки API берутся из непустых `GRAPHITI_API_*`, иначе из `LLM_API_*`. Без итогового API-ключа сервер ждёт настройки. |
| `mcpkit-cognee` | `http://mcpkit-cognee:8000/mcp` | `TRANSPORT_MODE=http`; `MCP_ALLOWED_HOSTS=mcpkit-cognee:*`; `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_ENDPOINT`; `EMBEDDING_PROVIDER`, `EMBEDDING_API_KEY`, `EMBEDDING_ENDPOINT`, `EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS`; каталоги данных фиксированы как `/cognee-storage/system` и `/cognee-storage/data`. Непустые сервисные настройки переопределяют глобальные значения по умолчанию. Точка входа ожидает ключ, только если соответствующий провайдер равен `openai`; требования других провайдеров проверяет сам сервис. |
| `mcpkit-memory-bank` | `http://mcpkit-memory-bank:8000/mcp` | `MEMORY_BANK_ROOT=/mcpkit/memory`; данные хранятся в томе `multfinite-mcp-kit-global-memory-data`. `mcp-proxy` принимает Streamable HTTP на порту 8000 внутри Docker-сети. |
| `mcpkit-gdrive` | `http://mcpkit-gdrive:8000/mcp` | `GDRIVE_CREDENTIALS_PATH=/mcpkit/gdrive/credentials.json`; контейнер ждёт OAuth-файл в томе `multfinite-mcp-kit-global-gdrive-data`. Получение учётных данных описано в README. |

Compose объявляет изолированные Docker-сети `multfinite-mcp-kit-global-{graphiti,cognee,memory,gdrive}` и тома для Cognee, GDrive и Memory Bank. Порты вспомогательных сервисов на хост не публикуются. Не меняйте имена сетей и томов без одновременного изменения URL регистрации и скрипта подключения MetaMCP. Официальные env-названия контейнеров и внутренние фиксированные параметры относятся к реализации Compose; основные пользовательские параметры находятся в таблице Linux `.env`.

## Прочие настройки

- `linux/seed-global.sql` задаёт серверы, их тип подключения, команды/аргументы, URL, пространства имён, конечные точки и параметры аутентификации по умолчанию. Эти настройки не являются `.env`-переменными. Имена серверов допускают латиницу, цифры, `_` и `-` (поэтому `io.draw` называется `io-draw`). Группы и URL конечных точек приведены в основном README.
- Новые конечные точки защищены аутентификацией по API-ключу. API-ключи создаются в интерфейсе MetaMCP, затем настраиваются в MCP-клиенте как `Authorization: Bearer <key>` или `X-API-Key: <key>`. Вспомогательные HTTP-сервисы сами по себе не проверяют этот ключ.
- `linux/run-global.sh` принимает команды `start`, `stop`, `restart`, `status`, `logs`, `services-logs`, `seed`, `apply-services`, `apply-metamcp-config`. Это аргументы запуска, а не ключи конфигурации.
- Linux использует фиксированный базовый путь `${HOME}/mcp-global/{config,data,metamcp}`. Windows по умолчанию использует `$env:USERPROFILE\mcp-local` и поддерживает переопределение через `$env:MCP_LOCAL_DIR`. Это переменная среды PowerShell, а не настройка Linux `.env`.
- Если исполняемый файл Docker отсутствует, Linux-инсталлятор устанавливает официальный Engine и модуль Compose и при необходимости добавляет текущего пользователя в группу `docker`. Группа даёт права, эквивалентные администраторским; после изменения членства может потребоваться новый вход. Уже установленный Docker, существующие APT-репозитории и связки ключей не заменяются; если демон недоступен или модуль отсутствует при наличии Docker, установщик сообщает об этом и не переустанавливает Docker.
- Linux-инсталлятор задаёт фиксированные имена контейнеров `neo4j-mcp` и `qdrant-mcp`, публикует Neo4j на `7474`/`7687`, Qdrant на `6333`/`6334`, включает модуль Neo4j `apoc` и хранит их данные в `~/mcp-global/data/{neo4j,qdrant}`. Существующие контейнеры с этими именами используются без проверки владельца/образа; `stop` и `restart` останавливают их по имени. Проверяйте конфликты до запуска. Порты, образы и пути монтирования не меняются переменными `.env` и не применяются к уже созданным контейнерам; пароль нового Neo4j контейнера читается из `NEO4J_PASSWORD`.
- Linux GLOBAL по умолчанию использует `http://localhost:12008`; его run-скрипт проверяет работоспособность на внутреннем порту `12008`. При изменении публичного адреса согласуйте Compose, `APP_URL`, `NEXT_PUBLIC_APP_URL` и URL клиентов. Windows LOCAL использует отдельную команду `set-ports`, описанную выше.
- `TEST_DATABASE_URL` используется только интеграционными тестами регистрации и сброса (`tests/test-global-seed.sh`, `tests/test-local-seed.sh`, `tests/test-windows-seed.sh`, `tests/test-windows-reset.sh`) и должен указывать на отдельную тестовую PostgreSQL БД, в которой можно создавать и удалять схемы. Пример: `TEST_DATABASE_URL='postgresql://user:password@localhost:5432/test_db' bash tests/test-windows-reset.sh`. Не используйте рабочую БД.

## Где применять изменения

- Linux API-ключи и параметры вспомогательных сервисов: `~/mcp-global/config/.env`; для Graphiti/Cognee выполнить `bash linux/run-global.sh apply-services`.
- Настройки существующих записей GitHub, Context7, Neo4j и Qdrant: менять через интерфейс MetaMCP. `start` не перезаписывает существующие записи; `seed` добавляет отсутствующие по правилам README.
- Публичный URL MetaMCP: задайте `APP_URL` / `NEXT_PUBLIC_APP_URL` в `~/mcp-global/config/.env` и выполните `bash linux/run-global.sh apply-metamcp-config`. Секрет аутентификации и параметры PostgreSQL настраиваются в `~/mcp-global/metamcp/.env` согласно правилам исходного проекта; заранее сохраните ручные файлы из записываемого слоя перед пересозданием приложения.
- Windows: для имеющихся серверов выполнить `install-local.ps1 -MetaMcpOnly`; настройки каталогов — в `config\local-settings.json`, ключ Obsidian и DSN DBHub — в `config\private\secrets.json`. После изменений выполнить `restart`. Старые `.env` и `mcp-local.json` автоматически не обновляют действующие настройки.
- Установщик Linux задаёт права `600` созданным `.env`; у уже существующих файлов проверяйте права самостоятельно. При синхронизации изменившегося URL управляющий скрипт также задаёт `600` файлу `.env` MetaMCP. Управляющий скрипт и установщик Windows настраивают ACL `config\private`, `runtime` и `logs` для текущего пользователя, SYSTEM и локальных администраторов; проверяйте права и для других каталогов, проектов и резервных копий. Не помещайте пароли/API-ключи в Git, публичный JSON, скриншоты, логи или команды, сохраняемые в истории команд оболочки.
