# Удаление Multfinite MCP Kit

Удаление и удаление **данных** — разные действия. Ни одна команда ниже не удаляет Docker целиком, другие Docker-проекты или записи в удалённом MetaMCP автоматически. Сначала определите, какие экземпляры и наборы установлены именно на этой машине, и сделайте проверяемые независимые резервные копии PostgreSQL, Neo4j, Qdrant, томов серверов, каталогов настроек, ключей и пользовательских проектов. Дамп БД внутри удаляемого тома не является независимой копией. Выберите правильные каталоги и Docker context; в них могут находиться созданные вами данные.

Новые экземпляры имеют `<каталог>/.mcpkit/state.json` с типом, каталогом, портом и именем Compose-проекта `mcpkit-meta-…` или `mcpkit-global-…`. Просмотрите файл перед удалением; не копируйте в чат `.mcpkit/.env` или другие секреты. Если состояние отсутствует/повреждено, автоматическое удаление откажет: восстанавливайте состояние из резервной копии или вручную проверяйте каждый ресурс. Не удаляйте неизвестные файлы и не используйте `docker system prune`, `docker volume prune`, `docker rm -f $(docker ps -aq)` или подобные общие команды.

## 1. Удалить новые отдельные Docker-проекты

Сначала остановите зависимых клиентов. Если MetaMCP был явно подключён к Docker-сети GLOBAL командой `link-global-metamcp`, отключите **каждый** такой экземпляр, пока оба проекта запущены, как описано в [руководстве](independent-installation.md#два-новых-docker-проекта-на-одной-машине). Удаление GLOBAL не удаляет записи из MetaMCP и не отключает произвольные чужие контейнеры от сети.

Команда `remove` показывает точный проект и просит ввести `REMOVE <имя-проекта>`. Она проверяет метки ресурсов и удаляет контейнеры и сеть **только этого проекта**, сохраняя именованные тома и каталог на диске. Записываемый слой удаляемого контейнера теряется: сохраните и его, если добавляли туда файлы. Если Docker Desktop/Engine остановлен, сначала запустите его; для удаления скрипт не запускает Docker только ради остановки.

### Linux

```sh
# Если для GLOBAL регистрировали автозапуск — сначала снимите его.
bash linux/run-global-servers.sh unregister-service "$HOME/mcp-kit/global"
bash linux/run-global-servers.sh status "$HOME/mcp-kit/global"
bash linux/run-global-servers.sh stop   "$HOME/mcp-kit/global"
bash linux/run-global-servers.sh remove "$HOME/mcp-kit/global"

bash linux/run-metamcp.sh status "$HOME/mcp-kit/metamcp/global"
bash linux/run-metamcp.sh remove "$HOME/mcp-kit/metamcp/global"
```

### Windows

```powershell
# Если для GLOBAL регистрировали автозапуск — сначала снимите его.
.\windows\run-global-servers.ps1 unregister-service "$env:USERPROFILE\mcp-kit\global"
.\windows\run-global-servers.ps1 status "$env:USERPROFILE\mcp-kit\global"
.\windows\run-global-servers.ps1 stop   "$env:USERPROFILE\mcp-kit\global"
.\windows\run-global-servers.ps1 remove "$env:USERPROFILE\mcp-kit\global"

.\windows\run-metamcp.ps1 status "$env:USERPROFILE\mcp-kit\metamcp\global"
.\windows\run-metamcp.ps1 remove "$env:USERPROFILE\mcp-kit\metamcp\global"
```

### Если нужно уничтожить и данные проекта

Только **после резервного копирования и проверки имени проекта** добавьте флаг удаления томов. Скрипт требует отдельного подтверждения `DELETE <имя-проекта>` и удаляет все именованные тома этого проекта, включая базы, токены GDrive и пользовательские данные в них. Это необратимо. Каталог установки при этом остаётся. Команду можно выполнить и после обычного `remove`, пока каталог состояния и файлы комплекта сохранены.

```sh
# Linux — выполните только для выбранного проекта:
bash linux/run-global-servers.sh remove "$HOME/mcp-kit/global" --delete-volumes
bash linux/run-metamcp.sh remove "$HOME/mcp-kit/metamcp/global" --delete-volumes
```

```powershell
# Windows — выполните только для выбранного проекта:
.\windows\run-global-servers.ps1 remove "$env:USERPROFILE\mcp-kit\global" -DeleteVolumes
.\windows\run-metamcp.ps1 remove "$env:USERPROFILE\mcp-kit\metamcp\global" -DeleteVolumes
```

Перед удалением GLOBAL отключите подключённые к нему MetaMCP через `link-global-metamcp` с `--unlink` / `-Unlink`. Команда `remove` заранее проверяет, не используется ли сеть другим контейнером, и в таком случае отказывается от удаления. Если проверка меток не прошла, разберитесь с владельцем и подключениями; не используйте принудительное удаление чужих ресурсов. Образы сохраняются. Для полного освобождения диска можно отдельно просмотреть метки через `docker image ls --filter label=com.multfinite.mcpkit.instance=<id>` и `docker image inspect`, затем удалить **только вручную проверенные теги этого проекта** через `docker image rm <точный-тег>` без `--force`. У одного образа могут быть другие теги или пользователи. На Windows добавьте `--context desktop-linux` после `docker`.

После остановки, удаления контейнеров и, при необходимости, томов просмотрите содержимое выбранного каталога, включая пользовательские данные и `.mcpkit`, и удалите каталог обычным файловым менеджером **только если он больше не нужен**. В нём находятся секреты, журнал регистраций, копия исходников и конфигурация; удаление каталога без томов усложнит восстановление. Не удаляйте родительский каталог, если в нём есть другие экземпляры.

## 2. Удалить LOCAL-серверы

### Новый Linux LOCAL

```sh
bash linux/run-local-servers.sh status "$HOME/mcp-kit/local"
bash linux/run-local-servers.sh stop   "$HOME/mcp-kit/local"
```

Управление останавливает только шлюз, ответивший на отдельный секрет управления, и его дочерние процессы; неизвестные PID не завершаются. Сохраните и проверьте каталог `~/mcp-kit/local` или явно выбранный вами другой каталог. Его `data/projects`, `data/writing`, база DBHub, данные управления рабочим столом, настройки и журналы могут содержать пользовательские файлы и секреты. `projectsDir` и `writingDir` могут указывать **за пределы** каталога комплекта: эти файлы автоматически не удаляются. После проверки удалите только выбранный каталог, если все его данные больше не нужны. `plocate`, его индекс, системные Node/Python, компиляторы и браузерные библиотеки автоматически не удаляются.

### Windows LOCAL

```powershell
.\windows\run-local-servers.ps1 status "$env:USERPROFILE\mcp-kit\local"
.\windows\run-local-servers.ps1 stop "$env:USERPROFILE\mcp-kit\local"
```

Для нового независимого LOCAL проверьте `%USERPROFILE%\mcp-kit\local` либо `$env:MCPKIT_LOCAL_DIR`/выбранный `-Directory`, пути `projectsDir`/`writingDir` и резервные копии. В каталоге могут находиться собственные данные, секреты, runtime и журналы; данные за его пределами не удаляются. Затем удалите только проверенный каталог в Проводнике. Если у вас **прежний связанный MetaMCP** в другом каталоге, сначала разберите его по следующему разделу: удаление его каталога раньше контейнеров/томов может лишить вас состояния и ключей. Пакеты, установленные глобально через WinGet, Python-интерпретаторы, кэши Chromium/uv и Everything могут использоваться другими программами; комплект их не удаляет. Удаляйте их штатными средствами системы только убедившись, что они больше никому не нужны.

## 3. Прежние объединённые установки

Новые команды `remove` намеренно **не принимают** старые установки и не мигрируют их.

### Windows: прежний `mcp-local` с MetaMCP

Посмотрите `config\private\metamcp-state.json` в выбранном `$env:MCP_LOCAL_DIR` или `%USERPROFILE%\mcp-local`; поле `project` содержит имя прежнего проекта. Не удаляйте и не публикуйте `metamcp.env`, `secrets.json` и состояние, пока нужны данные или восстановление. Штатная остановка прежней связки:

```powershell
.\windows\run-local.ps1 status
.\windows\run-local.ps1 stop
```

Скрипт проверяет состояние шлюза и метки своих контейнеров; если проверка не проходит, он откажет, а не будет использовать другой Docker context. Для просмотра ресурсов используйте имя из фактического состояния:

```powershell
$base = if ($env:MCP_LOCAL_DIR) { $env:MCP_LOCAL_DIR } else { "$env:USERPROFILE\mcp-local" }
$state = Get-Content -Raw -LiteralPath "$base\config\private\metamcp-state.json" | ConvertFrom-Json
$state.project
# Только список; дополнительно проверьте метку com.multfinite.mcpkit.instance и назначения томов.
docker --context desktop-linux ps -a --filter "label=com.docker.compose.project=$($state.project)"
docker --context desktop-linux volume ls --filter "label=com.docker.compose.project=$($state.project)"
docker --context desktop-linux network ls --filter "label=com.docker.compose.project=$($state.project)"
```

В этой версии нет общей безопасной команды удаления старого проекта. После независимой копии вручную проверьте **каждый** контейнер, том, сеть и образ, их метки и использование, затем удаляйте только точные подтверждённые ресурсы стандартными командами Docker. Не используйте `-v`/`volume rm`, если данные должны остаться. Резервные дампы внутри тома PostgreSQL удалятся вместе с томом. Только затем удалите выбранный каталог LOCAL, если его данные также больше не нужны.

### Linux: прежний `~/mcp-global`

Прежний `run-global.sh stop` останавливает контейнеры с фиксированными именами `neo4j-mcp` и `qdrant-mcp` **без проверки владельца**. Не запускайте его вслепую. Сначала проверьте, какие контейнеры и монтирования реально принадлежат вашей старой установке:

```sh
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker inspect --format '{{.Name}} {{json .Config.Labels}} {{json .Mounts}}' neo4j-mcp qdrant-mcp
```

Если имена отсутствуют, принадлежат другому проекту или у вас есть сомнения, не останавливайте и не удаляйте их. Старые дополнительные сервисы использовали Compose-проект `multfinite-mcp-kit-global`; старый MetaMCP мог использовать контейнеры `metamcp`/`metamcp-pg`, однако совпадение имени само по себе не доказывает владение. Проверьте Compose-метки, пути `~/mcp-global/metamcp`, `~/mcp-global/data`, реальные тома и их содержимое. После резервного копирования вручную остановите и удалите только подтверждённые контейнеры, сети, тома и образы. Если хотите сохранить данные, не удаляйте тома и `~/mcp-global/data`. Удаление Docker APT-репозитория, Docker Engine или членства в группе `docker` не выполняется автоматически: они могут быть нужны другим приложениям.

## 4. Записи в MetaMCP и копия репозитория

Регистрация создаёт приватные записи на целевом MetaMCP, в том числе на другой машине. Остановка/удаление локального kit не удаляет их. Если хотите очистить и MetaMCP, сохраните его базу и откройте приватный журнал `registrations/*.json`, чтобы сверить имена и UUID с интерфейсом. В интерфейсе вручную проверьте владельца, изменения и связи каждого объекта; сначала удаляют только подтверждённые конечные точки, затем принадлежащие kit пространства и серверы. **Не удаляйте** объект, если пользователь подключил к нему собственные записи или он нужен другим; операции MetaMCP могут каскадно удалить связанные данные. Скрипт не удаляет пользовательские и неопределённые записи.

После завершения и сохранения нужных файлов можно удалить саму копию репозитория/распакованную папку с командами. Проверьте в ней свои изменения и файлы перед удалением. Она не содержит автоматически все Docker-тома или внешние пользовательские проекты.
