# Три новых MetaMCP на Linux

Эта процедура предназначена для хоста с уже существующим независимым GLOBAL-набором. Она создаёт три **отдельные** базы и экземпляра:

| Экземпляр | Каталог | Доступ |
| --- | --- | --- |
| GLOBAL | `/metamcp/global-localhost` | порт `12008` на loopback; внешний HTTPS — через уже настроенный пользователем прокси |
| LOCAL WSL | `/metamcp/local-wslhost` | `http://localhost:12108` и `http://192.168.100.10:12108` |
| LOCAL VM | `/metamcp/local-vmhost` | `http://localhost:12208` и `http://192.168.100.10:12208` |

GLOBAL-серверы подключаются **только к GLOBAL MetaMCP**. Два LOCAL остаются пустыми до отдельного подключения соответствующих LOCAL-серверов. Глобальные сервисы используют прежние данные, а не новые копии.

## Запуск

Нужны Git, Node.js 20+, Docker Engine, Compose 2.24.4+, доступ к локальному Docker-сокету и права записи в `/metamcp`. У скрипта должен быть доступ к интернету для клонирования и сборки MetaMCP. Нужна интерактивная консоль. Системная служба Docker при необходимости включается при загрузке; может потребоваться `sudo`.

В актуальном checkout комплекта:

```sh
node linux/reinstall-three.mjs https://mcp.example.org 192.168.100.10
```

Внешний HTTPS-адрес и LAN-адрес — первые два аргумента. Третий — конкретный старый MetaMCP-проект с оставшимися томами; его можно опустить, если такой проект очищать не нужно. Адрес прокси и его настройки команда **не меняет**. Она попросит email и пароль администратора локально, а перед удалением старых MetaMCP — отдельное подтверждение `DELETE METAMCP`.

Пароль вводится скрыто и используется для создания одного администратора в каждом экземпляре. Регистрация новых пользователей закрывается до открытия порта. Ключ клиента сохраняется приватно в `.mcpkit/client-api-key` соответствующего каталога. Не присылайте пароль, ключи, cookies, содержимое `.env` или полные логи в переписку.

## Что изменяется и что сохраняется

- Скрипт проверяет метки Docker и владельца каталогов. Он удаляет только обнаруженные старые проекты MetaMCP в трёх указанных каталогах и явно указанный третий проект, включая их тома, собственные образы и данные. Неизвестные ресурсы, смонтированные каталоги и ресурсы, которыми пользуется другой контейнер, вызывают остановку. Если идентификацию подтвердить нельзя, удаление не начинается.
- Оба существующих набора GLOBAL, их данные, тома и bind mounts **не удаляются**. Для выбранного нового GLOBAL скрипт может запустить его существующие контейнеры и установить им `restart: unless-stopped`; пересборка или пересоздание GLOBAL не выполняются.
- Docker включается при загрузке, а новые контейнеры используют `unless-stopped`. Успешный автозапуск зависит также от доступности нужного LAN-адреса и Docker после загрузки.
- В GLOBAL создаются общие защищённые API-ключом серверы, пространства имён и endpoints с одинаковым именем на каждый сервер. Дополнительного префикса у имён MCP tools и prompts не добавляется. Чтобы имена оставались однозначными, в одном namespace должен быть **ровно один** сервер; встроенные MetaMCP admin tools в этом режиме не включаются. Добавление нескольких серверов в такой namespace приведёт к ошибке, а не к выбору случайного инструмента.
- Подключение GLOBAL использует отдельную внутреннюю сеть Docker. Записанная ссылка на неё сохраняется при пересоздании приложения штатной командой комплекта. Сеть и её владелец не переносятся.

**HTTP в LAN не шифрует пароли и API-ключи.** Пользуйтесь доступом только в доверенной сети. Владельцы Docker-сокета имеют административный доступ к контейнерам и их секретам.

## Если выполнение остановилось

До подтверждения скрипт не удаляет старые MetaMCP. После подтверждения удаление и создание состоят из нескольких операций; при ошибке часть работы уже могла выполниться. Скрипт сообщает об этом и сохраняет обнаруженные новые экземпляры. Повторный запуск той же команды может продолжить начатую установку, но при сообщении о неопределённом результате регистрации или неоднозначной идентичности сначала проверьте состояние вручную. Не удаляйте служебные файлы и тома наугад.

Зелёный запуск шлюза или приложения не гарантирует готовность каждого MCP-сервера. Graphiti, Cognee, Google Drive и GitHub могут требовать своих настроек или учётных данных; остальные серверы также могут ещё запускаться или сообщать об ошибке. Проверяйте состояние локально, не публикуя секреты.
