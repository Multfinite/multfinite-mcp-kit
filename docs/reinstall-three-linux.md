# Три MetaMCP на Linux: штатные команды

Используются обычные `install-metamcp.sh`, `connect-global.sh` и `run-metamcp.sh`. Существующий GLOBAL переустанавливать не нужно. Два LOCAL изначально пустые; GLOBAL подключается только к первому MetaMCP. Настройки reverse proxy команды не меняют.

Нужны Git, Node.js 20+, локальный Docker Engine, Compose 2.24.4+, доступ к Docker-сокету и права записи в выбранные каталоги. На хосте с systemd для автозапуска Docker можно выполнить:

```sh
sudo systemctl enable --now docker
```

В актуальной копии комплекта задайте email администратора и выполните установку. В примере каталоги **новые**, отличаются от старых и не перезаписывают их; замените HTTPS origin и LAN IP своими значениями. Порты должны быть свободны.

```sh
read -r -p 'Email администратора: ' ADMIN
bash linux/install-metamcp.sh --dir /metamcp/new-global --port 12008 --app-url https://mcp.example.org --clean-tools --setup --fresh --admin-email "$ADMIN" &&
bash linux/install-metamcp.sh --dir /metamcp/new-local-wsl --port 12108 --lan-ip 192.168.100.10 --allow-insecure-lan --clean-tools --setup --fresh --admin-email "$ADMIN" &&
bash linux/install-metamcp.sh --dir /metamcp/new-local-vm --port 12208 --lan-ip 192.168.100.10 --allow-insecure-lan --clean-tools --setup --fresh --admin-email "$ADMIN"
```

Каждый установщик локально и без отображения спросит пароль дважды, соберёт образ и создаст администратора до публикации порта. Пароль должен содержать 12–128 символов. Регистрация закрывается до публикации; личный клиентский API-ключ хранится в `.mcpkit/client-api-key` соответствующего экземпляра. `--fresh` отказывает при существующем состоянии и не перезаписывает чужой каталог.

Доступ: GLOBAL — указанный HTTPS origin, LOCAL WSL — `http://localhost:12108` и `http://192.168.100.10:12108`, LOCAL VM — соответствующие адреса на порту `12208`. HTTP в LAN не шифрует пароли и ключи. Используйте только доверенную сеть.

## Подключить установленный GLOBAL

Укажите **имя существующего независимого Docker-проекта**, а не путь к копии исходников:

```sh
read -r -p 'Docker-проект существующего GLOBAL: ' GLOBAL_PROJECT
bash linux/connect-global.sh --live-global "$GLOBAL_PROJECT" /metamcp/new-global
```

Команда проверяет контейнеры и изолированную сеть, при необходимости запускает только существующие контейнеры выбранного проекта, устанавливает им `restart: unless-stopped`, подключает выбранный MetaMCP и сохраняет связь при его пересоздании. Данные, тома, образы и контейнеры GLOBAL не удаляются и не пересоздаются. Для входа спросит email и пароль; передачу по незашифрованной внутренней Docker-сети нужно отдельно подтвердить строкой `TRUSTED TUNNEL` только при доверии этому хосту и сети.

Для каждого сервера создаются одноимённые общие сервер, namespace и защищённый API-ключом endpoint. Префикс к имени инструмента или промпта не добавляется. Для однозначной маршрутизации в namespace должен оставаться ровно один сервер; встроенные admin tools нельзя включать в этом режиме. Готовность шлюза не означает готовности каждого MCP-сервера: некоторые интеграции могут требовать настроек и учётных данных.

## Старые MetaMCP

После проверки новых экземпляров старый независимый MetaMCP с корректным состоянием удаляется штатной командой. Передавайте **только его фактический каталог** и отдельно подтвердите название проекта:

```sh
bash linux/run-metamcp.sh remove /путь/к/старому/metamcp --delete-volumes
```

Это необратимо удаляет контейнеры и тома выбранного MetaMCP, но оставляет его каталог и образы. Команда откажет, если каталог относится к GLOBAL. Два набора GLOBAL и их тома удалять не нужно. Если состояния старого MetaMCP нет или остались отдельные тома, не угадывайте владельца и не удаляйте их или старые каталоги вслепую: сначала проверьте метки, монтирования и использование другими контейнерами.

При любой ошибке остановитесь и проверьте состояние перед повтором: установка и регистрация состоят из нескольких операций. Сценарий `--fresh` намеренно не продолжает существующую установку; после прерывания настройки публикации отдельно доступна команда `bash linux/run-metamcp.sh setup КАТАЛОГ`, но сначала проверьте состояние экземпляра. Регистрация с неопределённым результатом требует проверки журнала и интерфейса, а не слепого повтора. Не отправляйте в переписку пароли, ключи, cookies, `.env` и полные логи.
